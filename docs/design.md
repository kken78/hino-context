# デザインシステム（画面に出す物の決まり）

画面・MCP・ファイルに出す物の、言葉、ページの型、部品、スタイルを決める。データの構造（SCHEMA.md、teigi/ の表）とは分ける。

- データの構造に、画面の文、欄の名前、並べ方を書かない。ここに書く。
- 画面の都合で、データの定義や字を直さない。
- 2つは、3節の対応の表だけでつなぐ。ページを作るツールは、言葉をこの文書から読む。ツールの中に、画面の言葉を書かない。
- この文書の言葉と型は、依頼者が決める。決まっていないものには「案」と書く。

## 1. 考え方

- 使う人は、職員、議員、住民。同じ物を、同じ言葉で出す。
- 並べるだけで、良し悪しは書かない。
- こちらの設計の言葉（印、列の名前、表の名前）を、画面に出さない。
- 言葉は、資料の言葉、法令・行政実務の言葉、すでに画面にある言葉の順に取る。取れなければ名前を作らず、実物の例で示す。

## 2. 画面に出す言葉

画面・MCP・ファイルに出す文で、左の列の言葉を使わず、右の列の言葉を使う。資料からの引用（資料の文、会議録の発言、資料の題、発言者の名前）の中は対象にしない。ツールはこの表を読み、作るページの文に左の列の言葉が残っていれば、ページを作らずに止まる。

- 左の列の「、」で区切った語を、それぞれ1つの語として見る。「（」から「）」までは語の注で、語に含めない。
- 右の列の言葉の一部として出る場合（「論点」の中の「点」、「数値」の中の「値」）は、残っていると見ない。
- 次の言葉の一部として出る場合も、残っていると見ない：時点。
- 確認する所が「リンクの名前」の行は、リンクの文字だけを見る。「文」の行は、画面に出るすべての文を見る。

| 使わない | 使う | 確認する所 |
| --- | --- | --- |
| 事項、点 | 論点 | 文 |
| 題材 | テーマ | 文 |
| 当たる（「この事項に当たる」） | 〜に関する | 文 |
| 記載 | 記述 | 文 |
| 段落（リンクの名前として） | 会議録 | リンクの名前 |
| 値 | 金額、数値 | 文 |
| 性質 | （列を置かない。区分は「議会での答弁」「町の資料」） | 文 |
| 対応 | （使わない） | 文 |
| 原典、出典 | もとの資料 | 文 |
| 開けます | 確認できます | 文 |
| 見本 | 試作 | 文 |

## 3. データの構造との対応（数値のページ、資料の表のページ）

左の列は、SCHEMA.md にある印か列。右の2列が、画面での扱い。言葉はどれも案。

- ページを作るツールは、左の列の字を鍵として行を引く。行を足すときも、左の列は同じ形（「定義の表 列」「数値の表 列」「文書の表 列」「文書の部分の表 列」「時点の関係 印」のどれか）か、決めた形（「shiryo が発言」「shiryo が計画・町の資料」「文書の部分（bubun・retsu から親をたどった並び）」「bubun が空」「同じ定義の数値がある、ほかの文書」）で書く。
- 「出し方」の列の、列の説明「」の中の字は、ツールが表の列の見出しの下に出す。
- 画面の言葉が「（言葉を出さない）」「（出さない）」の行は、画面に出さないことを決めた行。

## 4. ページの型（数値のページ）

上から順に、次のものを置く。

1. 題（定義の名前）と、頭の文（非公式の試作であること、もとの資料をもとに作成したこと、良し悪しは書いていないこと）。
2. この数値について（定義の欄）。
3. 数値の表。
   - 行は時期、列は時点の関係（事前、年度の途中、事後の順）。その定義に1行も無い列は出さない。
   - 内訳がある定義は、内訳ごとに表を分ける。
   - 時点の関係が無い行は、表の下に、理由ごとに並べる。
   - どの行にも時点の関係が無い定義（開園の時期）は、資料の日付の古い順に、1つの表に並べる（2026-11-21 の依頼者の決定）。
   - 同じ時期の事後の数値が、資料によって違うときは、「資料の間で、数値が一致していません」と出す。数値は計算しない。
4. それぞれの数値の、もとの資料（数値ごとの欄）。
5. このページに載せていないもの。
6. 終わりの文（正確な内容はもとの資料で確認すること、公式のものではないこと、作った日）。

表に行が無い時期を、「無い」と書かない。空の欄は空のままにする。

### 資料の表のページ

資料の表1つを、1ページにする。上から順に、次のものを置く。

1. 題（表の題）と、頭の文。
2. 資料の名前、版の表記（あれば）、資料の日付、ページ。
3. 表の上の見出し（文書の部分の表で、表の親をたどった見出し）。
4. 表。行と列は、資料の表と同じ順にする。行と列の見出しは、資料の字のままにする。列のまとまりの見出しがある場合は、列の見出しの上の行に出す。torikata が「読んだ」で、chu に確認の記録が無い表、行、列の見出しには「（未確認）」を付け、表の下に、その意味を書いた決まった文を出す。
5. もとの資料へのリンク。
6. 資料が根拠としているもの。
7. 同じ定義の数値がある資料（資料の名前、版の表記（あれば）、資料の日付、ページ）。
8. このページについて。

「資料の該当部分」は、このページには出さない。表が、資料の該当部分である。

## 5. 部品とスタイル

まだ決めていない。方針だけを書く。

- 自分で作らず、デジタル庁デザインシステムを土台にする。使う前に、公式の利用規約を確認する。
- インターネットにつながらない環境でも開けるように、外から何も読み込まない1つの HTML にする。
- 中身は、使う人に見ていただくページを作るときに決める。

## 6. ツールの検査

- 画面に出る文に、2節の「使わない」言葉が残っていない（資料からの文は除く）。
- データの側が返す印のすべてに、3節の行がある。
- 3節の「データの側」が、SCHEMA.md にある印か列である。
- ページを作るツールの中に、3節にある言葉が書かれていない（言葉は、この文書から読む）。
