# デザインシステム（画面に出す物の決まり）

画面・MCP・ファイルに出す物の、言葉、ページの型、部品、スタイルを決める。データの構造（SCHEMA.md、teigi/ の表）とは分ける。

- データの構造に、画面の文、欄の名前、並べ方を書かない。ここに書く。
- 画面の都合で、データの定義や字を直さない。
- 2つは、3節の対応の表だけでつなぐ。ページを作るツールと、MCP の応答を作るツール（tools/build_mcp.py）は、言葉をこの文書から読む。ツールの中に、画面の言葉を書かない。MCP の応答の文も、この文書の言葉で作る。
- この文書の言葉と型は、依頼者が決める。決まっていないものには「案」と書く。

## 1. 考え方

- 使う人は、職員、議員、住民。同じ物を、同じ言葉で出す。
- 並べるだけで、良し悪しは書かない。
- こちらの設計の言葉（印、列の名前、表の名前）を、画面に出さない。
- 言葉は、資料の言葉、法令・行政実務の言葉、すでに画面にある言葉の順に取る。取れなければ名前を作らず、実物の例で示す。

## 2. 画面に出す言葉

画面・MCP・ファイルに出す文で、左の列の言葉を使わず、右の列の言葉を使う。資料からの引用（資料の文、会議録の発言、資料の題、発言者の名前）の中は対象にしない。hino-ronten の記録のうち、資料の字か記録の名前である所（施設の記録の value・target・quote、過程の記録の name・quote、施設の参照表の name・aliases）も、資料からの引用と同じ扱いにし、対象にしない。施設の記録の項目（aspect）と区分（kind）は、決まった少数の言葉で、欄の見出しと同じ働きをするので、対象にする（当たればページを作らずに止まる。その場合は、画面での出し方を依頼者が決める）。ツールはこの表を読み、作るページの文に左の列の言葉が残っていれば、ページを作らずに止まる。

- 左の列の「、」で区切った語を、それぞれ1つの語として見る。「（」から「）」までは語の注で、語に含めない。
- 右の列の言葉の一部として出る場合（「論点」の中の「点」、「数値」の中の「値」）は、残っていると見ない。
- 次の言葉の一部として出る場合も、残っていると見ない：時点、アレルギー対応、点検、拠点、交差点、問題点、利点、重点、視点、大型店の出店と町の対応、工場の騒音への苦情と対応、道路整備の要望への対応の優先順位、流域下水道の更新と災害時の対応、登校を控える児童生徒への対応、通学区域柔軟化対応モデル事業、弾道ミサイル飛来時の学校の対応、危険箇所の要望と対応、車中泊などの避難者への対応、災害対応型自動販売機の設置、スポーツ協会の提案書への対応、時代の変化に対応した計画的な都市計画、時代に対応したICT技術の活用、新型コロナの感染予防と町の対応。

- 「点検」は会議録と町の資料の言葉で、事項の名前「公共施設の点検と安全管理」（依頼者の決定 2026-11-28）にある。「点」を使わないのは、論点を「点」と書かないためで、この語は当たらない。
- 拠点から視点までの6つは、ふつうの語で、論点を「点」と書くものではない。「大型店の出店と町の対応」から「時代に対応したICT技術の活用」までは、総合計画の分野の読み取りの論点の名前（作業者の案。2026-11-28）と、総合計画の基本施策の名前（入力の字。最後の2つ）で、「対応」は会議録と計画の言葉である。データどうしの対応を指す言い方ではないので、当たらない。論点の名前は、依頼者が1つずつ見るときに変わることがある（2026-11-28。案）。「新型コロナの感染予防と町の対応」は、総合計画の分野⑰のまとまりの名前（作業者の案。2026-11-28）で、「対応」は同じ意味の言葉なので、当たらない。

## 4. ページの型（数値のページ）

上から順に、次のものを置く。

1. 題（項目の名前）と、頭の文（非公式の試作であること、もとの資料をもとに作成したこと、良し悪しは書いていないこと）。
2. この項目について（項目の欄）。
3. 数値の表。
   - 行は時期、列は時点の関係（ato、tochu、mae の順。画面の言葉は3節）。その項目に1行も無い列は出さない。
   - 内訳がある項目は、内訳ごとに表を分ける。
   - 時点の関係が無い行は、表の下に、理由ごとに並べる。
   - どの行にも時点の関係が無い項目（開園の時期）は、資料の日付の古い順に、1つの表に並べる（2026-11-21 の依頼者の決定）。
   - 同じ時期の mae の数値が、資料によって違うときは、「資料の間で、数値が一致していません」と出す。数値は計算しない。
4. それぞれの数値の、もとの資料（数値ごとの欄）。
5. このページに載せていないもの。
6. 終わりの文（正確な内容はもとの資料で確認すること、公式のものではないこと、作った日）。

表に行が無い時期を、「無い」と書かない。空の欄は空のままにする。

### 資料の表のページ

資料の表1つを、1ページにする。上から順に、次のものを置く。

1. 題（表の題）と、頭の文。
2. 資料の名前、版の表記（あれば）、資料の日付、ページ。
3. 表の上の見出し（資料の中の場所の表で、表の親をたどった見出し）。
4. 表。行と列は、資料の表と同じ順にする。行と列の見出しは、資料の字のままにする。列のまとまりの見出しがある場合は、列の見出しの上の行に出す。torikata が「読んだ」で、chu に確認の記録が無い表、行、列の見出しには「（未確認）」を付け、表の下に、その意味を書いた定型文を出す。
5. もとの資料へのリンク。
6. 資料が根拠としているもの。
7. 同じ項目がある資料（資料の名前、版の表記（あれば）、資料の日付、ページ）。
8. このページについて。

「資料の該当部分」は、このページには出さない。表が、資料の該当部分である。

### テーマのページ

テーマ1つを、1ページにする（tools/build_theme.py）。テーマの名前、施設、資料は、hino-ronten のテーマの定義から引く（SCHEMA.md 7.7）。上から順に、次のものを置く。

1. 題（テーマの名前）と、頭の文。
2. 町の説明。資料の名前と、資料の文（テーマの表の、shu が「説明の文」の行）。行が無いテーマは、見出しも出さない。
3. これまでの経過。時期、内容、資料の文、もとの資料の4つの列。時期（from の年月）の古い順に並べ、同じ年月なら step の順にする。行は hino-ronten の過程の記録の確定済みの行で、内容は、その記録の名前のまま出す。
   - 改正前の資料と、改正前と改正後で違う内容（2026-11-27 の依頼者の決定。見出しの言葉は 2026-11-27 に「数値」から「内容」に修正）：行のもとの資料が、資料どうしの関係の表で hyogen が「一部改正」の行の kara であるとき、その行の下に1行を足す。その行には、「改正前」の言葉と、e の資料の名前（もとの資料へのリンク）を出し、その下に「改正前と改正後で違う数値」の見出しと kaisei-hani の文を置く。見出しの下には、2つの資料の、同じ項目の、改正前と改正後の組み合わせ（SCHEMA.md 6.2。tools/suji.py の1か所で作る）のうち、atai が違う組み合わせを kaisei-tsui の文（改正前と改正後は kaisei-atai の文）で、kara の資料にだけある数値を kaisei-kuwawaru の文で、e の資料にだけある数値を kaisei-nai の文で、この順に並べる。それぞれの中は、項目の表の順にする。項目の名前は、数値のページへのリンクにする（数値のページがある項目だけ。tools/build_suji.py でページを作れる項目）。
   - 組み合わせた2行の atai が同じ数値は出さない。atai が違う組み合わせも、片方の資料にだけある数値も無いときは、「改正前」の行だけを出し、見出しは出さない。幼保では、13行めの1行だけに出る。
   - SCHEMA.md 6.2 の条件 (2)（nendo が空で、施設が同じ）で組み合わせた数値は、jiten では行が分からないので、項目の名前のあとに、行の見出し（資料の中の場所の表の name）を添える。片方の資料にだけある数値の時期の所にも、jiten の代わりに行の見出しを出す。段落の見出し（SCHEMA.md 7.2）を指す数値は、行の見出しの代わりに、段落の見出しの name を添える（2026-11-27。再編整備計画 34ページの段落と、開園の時期の再編整備計画の2行）。
   - 画面には、ID を出さない。
4. 町内の施設の表（テーマの表の、shu が「施設の表」の行が指す表）。
   - 行は、その表の行か列のうち、shisetsu があるもの。行の見出しは name のまま。
   - 欄は、matome（言葉を出さない。欄の見出しは空。matome のある行が無ければ欄を出さない）、運営（施設の記録の aspect「運営」のうち、source のページが施設の表のページと同じ行の value）、施設の ID の組が同じ数値（項目ごとに1列。列の見出しは項目の name。項目の表の順に並べる）。
   - 数値の資料の名前と時期、表の資料の名前とページ、運営のもとは、表の上の定型文で示す。nendo が空の数値（資料の日付で並べる項目の数値。所在地など）は、時期の括弧を出さない。jiten に資料の号を書いているので、資料の名前と重なるためである。
   - 行が複数の施設を指すとき（基本構想の「桜谷こども園」）は、施設の参照表の name を小さく添え、施設ごとの記述へのページ内リンクにする。
   - テーマの施設のうち、この表に無い施設は、表の下に名前を並べる（施設ごとの記述へのページ内リンク）。
   - 施設の割り当てが未確認の行（SCHEMA.md 7.2）がある表は、印の言葉が決まっていないので、ページを作らずに止まる。
   - 欄に出す数値から、テーマの資料の表（施設の表として指定した表を除く）の欄を除く。その欄は、6の「資料の表での記述」にだけ出す。同じ内容を2か所に出さない（2026-11-25 の依頼者の了承）。テーマの資料の見出しで、shisetsu があるもの（SCHEMA.md 7.2 の段落の見出し）を指す数値も、欄に出さない（2026-11-27）。2つの版の段落の文が1つの欄に並び、どちらの版の文かが分からなくなるためである。段落は表ではないので、6の「資料の表での記述」にも出さない。テーマのページで段落の文が出るのは、3の「改正前と改正後で違う内容」と、6の記録の表（hino-ronten の施設の記録に、同じ段落の文を引用した確定済みの行がある）である。いま施設の表に出ている数値（定員と園児在籍数は施設の表そのもの、所在地は広報ひの 2024年10月号でテーマの資料ではない）と運営は、変わらない。
5. 資料。資料どうしの関係の表のうち、kara か e がテーマの資料の行の資料を、資料の日付の古い順に並べ、それぞれが、ほかの資料について書いている文と、その文が指す資料の名前を出す。同じ文で相手が複数なら、1つにまとめる。
6. 施設ごとの記述。テーマの施設ごとに、施設の記録の確定済みの行を、資料の日付（source_date）の古い順に並べる。ただし、資料の一覧の表で hiduke が空の資料（資料に日付の記述が無い資料）の行は、最後に置く。年度だけが分かる資料と、資料に日付の記述が無い資料がある場合は、表の上の文に hiduke-nendo-setsumei と hiduke-nashi-setsumei の文を添える。数値のページの「資料の日付の順に並べた数値」、テーマのページの資料の表、資料の表での記述、資料の表のページの「同じ項目がある資料」も、資料に日付の記述が無い資料を最後に置き、ある場合は hiduke-nashi-setsumei の文を添える（2026-11-27 の修正）。施設の表にある施設を、表の行の順に先に置く。項目と区分は、記録の言葉のまま出し、区分が資料の時点での区分であることを、表の上の定型文で示す。施設の参照表に前の名前があれば出す。
   - 資料の表での記述（案。2026-11-25）：施設ごとに、記録の表の下に置く。行は、資料の中の場所の表の行か列のうち、shisetsu にその施設の ID があり、親の表がテーマの資料（テーマの定義の資料と系列）の表で、テーマの表で施設の表として指定した表ではないもの。列は、もとの資料（資料の名前、版、ページ。リンク）、表の題、行の見出し（name のまま）、欄（その行の欄を、列の見出しと内容の組で並べる。内容は数値と内容の表の atai）。資料の日付の古い順に並べ、版の違う資料は別の行にする。該当する行が無い施設には、見出しも出さない。

   - 施設の割り当てが未確認の行（SCHEMA.md 7.2）があれば、施設の表と同じく、ページを作らずに止まる。見出しの未確認の印は、資料の表のページと同じく付ける。
7. このページについて。

- 資料の名前：資料の一覧の表にある資料は、namae と、括弧に版の表記と資料の日付（資料の表のページと同じ）。広報ひのは koho の文（資料の一覧の表にあれば hiduke、無ければ hino-town-docs の sources.tsv の date と title）。資料の一覧の表に無い町の資料は sources.tsv の title。sources.tsv の date が空で fiscal_year がある資料は、title のあとの括弧に、年度を nendo の文で出す（2026-11-27 の修正）。会議録は kaigiroku-kubun の文で、日付と、町の答弁か議員の発言かを出し、発言者の名前は出さない。町の答弁か議員の発言かは、発言者の役職（入力の会議録の索引の role）から、ツールが決める。hino-ronten の記録の note は使わない。

### MCP の応答

MCP サーバーの形（ツール、引数、続き、JSON の形）は docs/mcp.md に書く。ここには、応答の文の型を書く。応答の文は、見出し（`#`）と箇条書き（`-`）の文で、HTML は入れない。言葉は3節の表から引く。

- どの応答も、1行目は mcp-atama の文、2行目は題（`# `）。続きがある応答は、題の下に mcp-tsuzuki-dai の文（何番目か）を出し、終わりに mcp-tsuzuki の文を出す。
- 名前のあとの括弧に、ツールの引数の名前と、その引数に使う ID を、mcp-kagi の文で出す（例：「待機児童数（item：taiki）」）。使う人の生成AIが、次に呼ぶツールの引数を、応答から取れるようにするためである。
- 資料の名前は、テーマのページと同じ（資料の一覧の表にある資料は、名前と、括弧に版の表記と資料の日付。広報ひのは koho の文。会議録は kaigiroku-kubun の文で、発言者の名前は出さない）。総合計画（plan の ID）は資料の一覧の表の名前。外部の公的な資料（ext の ID）は SCHEMA.md §4 の出典の名前。URL は、資料の名前の下か横に「もとの資料：URL」と出す。URL が無い資料は link-nashi の文。
- 1回の応答は、文字数で上限を決める（tools/build_mcp.py の JOGEN。いまは 6,000 字）。超える組は、区切りのよい所（資料ごと、表ごと、項目ごと）で分ける。1つの項目の途中では分けない。

数値（item）

1. 題は項目の名前と ID。kettei が「案」なら「項目の表 kettei が「案」」の文。項目の欄（数値のページの2と同じ。空の欄は出さない）。
2. 時点の関係の説明（mcp-kankei-setsumei の文と、その項目に出てくる印の言葉と列の説明）。未確認の印が付く数値があれば mikakunin-setsumei の文。breakdown=1 の組は mcp-uchiwake-dake の文。
3. 資料の間で、数値が一致していません（chigau）。数値のページと同じ判定で、該当する時期があるときだけ出す。時期（内訳があれば内訳も）ごとに、mcp-chigau-gyo の文で、数値と資料の名前を並べ、chigau-setsumei の文を添える。どちらが正しいかは書かない。
4. 資料ごとの数値（単位の無い項目は内容。mcp-midashi-suji）。資料（計画と町の資料はページ、会議録は発言）ごとに、資料の日付の古い順に並べる。年度だけが分かる資料は、その年度の4月として並べる。外部の公的な資料はその後、資料に日付の記述が無い資料はさらにその後に置き、もとの資料が無い数値は最後に置く。年度だけが分かる資料か、資料に日付の記述が無い資料があれば、hiduke-nendo-setsumei か hiduke-nashi-setsumei の文を添える。資料ごとに、資料の名前、もとの資料の URL、資料が根拠としているもの。
5. 数値ごとに、資料での時期の書き方（jiten）と数値、時点の関係の言葉（括弧）、資料での呼び方、確認の状態（chu のうち確認の記録の字だけ）。その下に、掲載されている所（未確認の印を含む）と、資料の該当部分。数値が無い状態は、調べた結果と状態の字、調べた範囲、調べた日。
6. breakdown を付けない組は、内訳（kubun）の無い数値だけを出し、breakdown=1 の組は、内訳のある数値だけを、資料の中で、内訳ごとにまとめて出す（内訳の見出しの下に、その内訳の数値）。内訳のある数値がある組では、breakdown を付けない応答の終わりに mcp-uchiwake の文を出す。内訳の無い数値が1つも無い組は、mcp-uchiwake-nomi の文を出す。
7. document に資料の ID を付けた組は、その資料の数値だけを出す。表に行が無い時期を「無い」と書かない。

資料の表（document。document と table）

1. 題は表の題と番号。資料の名前とページ、表の上の見出し、もとの資料の URL、資料が根拠としているもの。
