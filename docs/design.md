# デザインシステム（画面に出す物の決まり）

画面・MCP・ファイルに出す物の、言葉、ページの型、部品、スタイルを決める。データの構造（SCHEMA.md、teigi/ の表）とは分ける。

- データの構造に、画面の文、欄の名前、並べ方を書かない。ここに書く。
- 画面の都合で、データの定義や字を直さない。
- 2つは、3節の対応の表だけでつなぐ。ページを作るツールは、言葉をこの文書から読む。ツールの中に、画面の言葉を書かない。
- この文書の言葉と型は、依頼者が決める。決まっていないものには「案」と書く。

## 1. 考え方

- 使う人は、職員、議員、住民。同じ物を、同じ言葉で出す。
- 並べるだけで、良し悪しは書かない。
- こちらの設計の言葉（印、列の名前、表の名前）を、画面に出さない。
- 言葉は、資料の言葉、法令・行政実務の言葉、すでに画面にある言葉の順に取る。取れなければ名前を作らず、実物の例で示す。

## 2. 画面に出す言葉

画面・MCP・ファイルに出す文で、左の列の言葉を使わず、右の列の言葉を使う。資料からの引用（資料の文、会議録の発言、資料の題、発言者の名前）の中は対象にしない。hino-ronten の記録のうち、資料の字か記録の名前である所（施設の記録の value・target・quote、過程の記録の name・quote、施設の参照表の name・aliases）も、資料からの引用と同じ扱いにし、対象にしない。施設の記録の項目（aspect）と区分（kind）は、決まった少数の言葉で、欄の見出しと同じ働きをするので、対象にする（当たればページを作らずに止まる。その場合は、画面での出し方を依頼者が決める）。ツールはこの表を読み、作るページの文に左の列の言葉が残っていれば、ページを作らずに止まる。

- 左の列の「、」で区切った語を、それぞれ1つの語として見る。「（」から「）」までは語の注で、語に含めない。
- 右の列の言葉の一部として出る場合（「論点」の中の「点」、「数値」の中の「値」）は、残っていると見ない。
- 次の言葉の一部として出る場合も、残っていると見ない：時点。
- 確認する所が「リンクの名前」の行は、リンクの文字だけを見る。「文」の行は、画面に出るすべての文を見る。

| 題材 | テーマ | 文 |
| 当たる（「この事項に当たる」） | 〜に関する | 文 |
| 記載 | 記述 | 文 |
| 段落（リンクの名前として） | 会議録 | リンクの名前 |
| 値 | 金額、数値 | 文 |
| 性質 | （列を置かない。区分は「議会での答弁」「町の資料」） | 文 |
| 対応 | （使わない） | 文 |
| 原典、出典 | もとの資料 | 文 |
| 開けます | 確認できます | 文 |
| 見本 | 試作 | 文 |

## 3. データの構造との対応（数値のページ、資料の表のページ、テーマのページ）

左の列は、SCHEMA.md にある印か列。右の2列が、画面での扱い。言葉はどれも案。

- ページを作るツールは、左の列の字を鍵として行を引く。行を足すときも、左の列は同じ形（「定義の表 列」「数値の表 列」「文書の表 列」「文書の部分の表 列」「文書どうしの関係の表 列」「テーマの表 列」「テーマの定義 列」「施設の参照表 列」「施設の記録 列」「過程の記録 列」「時点の関係 印」のどれか。列は「、」で区切って2つ以上書ける）か、決めた形（「shiryo が発言」「shiryo が計画・町の資料」「文書の部分（bubun・retsu から親をたどった並び）」「bubun が空」「同じ定義の数値がある、ほかの文書」「会議録の発言者の役職が「数字＋番」」「会議録の発言者の役職が、議長でも「数字＋番」でもない」）で書く。
- テーマの定義（hino-ronten ref/themes.tsv）、施設の参照表（ref/shisetsu.tsv）、施設の記録（records/shisetsu.tsv）、過程の記録（records/katei.tsv）の列は、SCHEMA.md §1 の入力の表の列である。会議録の発言者の役職は、入力の会議録の索引の role である。
- 「出し方」の列の、列の説明「」の中の字は、ツールが表の列の見出しの下に出す。
- 画面の言葉が「（言葉を出さない）」「（出さない）」の行は、画面に出さないことを決めた行。

## 4. ページの型（数値のページ）

上から順に、次のものを置く。

1. 題（定義の名前）と、頭の文（非公式の試作であること、もとの資料をもとに作成したこと、良し悪しは書いていないこと）。
2. この数値について（定義の欄）。
3. 数値の表。
   - 行は時期、列は時点の関係（事前、年度の途中、事後の順）。その定義に1行も無い列は出さない。
   - 内訳がある定義は、内訳ごとに表を分ける。
   - 時点の関係が無い行は、表の下に、理由ごとに並べる。
   - どの行にも時点の関係が無い定義（開園の時期）は、資料の日付の古い順に、1つの表に並べる（2026-11-21 の依頼者の決定）。
   - 同じ時期の事後の数値が、資料によって違うときは、「資料の間で、数値が一致していません」と出す。数値は計算しない。
4. それぞれの数値の、もとの資料（数値ごとの欄）。
5. このページに載せていないもの。
6. 終わりの文（正確な内容はもとの資料で確認すること、公式のものではないこと、作った日）。

表に行が無い時期を、「無い」と書かない。空の欄は空のままにする。

### 資料の表のページ

資料の表1つを、1ページにする。上から順に、次のものを置く。

1. 題（表の題）と、頭の文。
2. 資料の名前、版の表記（あれば）、資料の日付、ページ。
3. 表の上の見出し（文書の部分の表で、表の親をたどった見出し）。
4. 表。行と列は、資料の表と同じ順にする。行と列の見出しは、資料の字のままにする。列のまとまりの見出しがある場合は、列の見出しの上の行に出す。torikata が「読んだ」で、chu に確認の記録が無い表、行、列の見出しには「（未確認）」を付け、表の下に、その意味を書いた決まった文を出す。
5. もとの資料へのリンク。
6. 資料が根拠としているもの。
7. 同じ定義の数値がある資料（資料の名前、版の表記（あれば）、資料の日付、ページ）。
8. このページについて。

「資料の該当部分」は、このページには出さない。表が、資料の該当部分である。

### テーマのページ

テーマ1つを、1ページにする（tools/build_theme.py）。テーマの名前、施設、資料は、hino-ronten のテーマの定義から引く（SCHEMA.md 7.7）。上から順に、次のものを置く。

1. 題（テーマの名前）と、頭の文。
2. 町の説明。資料の名前と、資料の文（テーマの表の、shu が「説明の文」の行）。行が無いテーマは、見出しも出さない。
3. これまでの経過。時期、内容、資料の文、もとの資料の4つの列。時期（from の年月）の古い順に並べ、同じ年月なら step の順にする。行は hino-ronten の過程の記録の確定済みの行で、内容は、その記録の名前のまま出す。
4. 町内の施設の表（テーマの表の、shu が「施設の表」の行が指す表）。
   - 行は、その表の行か列のうち、shisetsu があるもの。行の見出しは name のまま。
   - 欄は、matome（言葉を出さない。欄の見出しは空。matome のある行が無ければ欄を出さない）、運営（施設の記録の aspect「運営」のうち、source のページが施設の表のページと同じ行の value）、施設の鍵の組が同じ数値（定義ごとに1列。列の見出しは定義の name。定義の表の順に並べる）。
   - 数値の資料の名前と時期、表の資料の名前とページ、運営のもとは、表の上の決まった文で示す。nendo が空の数値（資料の日付で並べる定義の数値。所在地など）は、時期の括弧を出さない。jiten に資料の号を書いているので、資料の名前と重なるためである。
   - 行が複数の施設を指すとき（基本構想の「桜谷こども園」）は、施設の参照表の name を小さく添え、施設ごとの記述へのページ内リンクにする。
   - テーマの施設のうち、この表に無い施設は、表の下に名前を並べる（施設ごとの記述へのページ内リンク）。
   - 施設の割り当てが未確認の行（SCHEMA.md 7.2）がある表は、印の言葉が決まっていないので、ページを作らずに止まる。
   - 欄に出す数値から、テーマの資料の文書の表（施設の表として指定した表を除く）の欄を除く。その欄は、6の「資料の表での記述」にだけ出す。同じ内容を2か所に出さない（2026-11-25 の依頼者の了承）。いま施設の表に出ている数値（定員と園児在籍数は施設の表そのもの、所在地は広報ひの 2024年10月号でテーマの資料ではない）と運営は、変わらない。
5. 資料。文書どうしの関係の表のうち、kara か e がテーマの資料の行の文書を、資料の日付の古い順に並べ、それぞれが、ほかの資料について書いている文と、相手の資料の名前を出す。同じ文で相手が複数なら、1つにまとめる。
6. 施設ごとの記述。テーマの施設ごとに、施設の記録の確定済みの行を、資料の日付（source_date）の古い順に並べる。施設の表にある施設を、表の行の順に先に置く。項目と区分は、記録の言葉のまま出し、区分が資料の時点での区分であることを、表の上の決まった文で示す。施設の参照表に前の名前があれば出す。
   - 資料の表での記述（案。2026-11-25）：施設ごとに、記録の表の下に置く。行は、文書の部分の表の行か列のうち、shisetsu にその施設の鍵があり、親の表がテーマの資料（テーマの定義の資料と系列）の文書の表で、テーマの表で施設の表として指定した表ではないもの。列は、もとの資料（資料の名前、版、ページ。リンク）、表の題、行の見出し（name のまま）、欄（その行の欄を、列の見出しと内容の組で並べる。内容は数値の表の atai）。資料の日付の古い順に並べ、版の違う文書は別の行にする。該当する行が無い施設には、見出しも出さない。
   - 実物の例：再編整備計画 27ページの表「〇町立幼児教育保育施設の再編整備について」は、2つの版（2025年3月の版と、令和８年６月一部改正の版）を、別の行として出す。西大路幼稚園には2行が出る。新こども園とわらべ保育園には、この表に行が無いので出さない。
   - 施設の割り当てが未確認の行（SCHEMA.md 7.2）があれば、施設の表と同じく、ページを作らずに止まる。見出しの未確認の印は、資料の表のページと同じく付ける。
7. このページについて。

- 資料の名前：文書の表にある文書は、namae と、括弧に版の表記と資料の日付（資料の表のページと同じ）。広報ひのは koho の文（文書の表にあれば hiduke、無ければ hino-town-docs の sources.tsv の date と title）。文書の表に無い町の資料は sources.tsv の title。会議録は kaigiroku-kubun の文で、日付と、町の答弁か議員の発言かを出し、発言者の名前は出さない。町の答弁か議員の発言かは、発言者の役職（入力の会議録の索引の role）から、ツールが決める。hino-ronten の記録の note は使わない。
- 過程の記録と施設の記録の quote は、もとの資料の本文と照合する（SCHEMA.md §3。過程の記録は sources の1つ目の資料）。合わない行があれば、ページを作らずに止まる。

## 6. ツールの検査

- 画面に出る文に、2節の「使わない」言葉が残っていない（資料からの文は除く）。
- データの側が返す印のすべてに、3節の行がある。
- 3節の「データの側」が、SCHEMA.md にある印か列である。
- ページを作るツールの中に、3節にある言葉が書かれていない（言葉は、この文書から読む）。
- 3節の表の行を、ページを作るツール（tools/build_suji.py、tools/build_hyo.py、tools/build_theme.py）のどれかが引いている。
