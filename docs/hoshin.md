# hino-context の方針（2026-11-18）

依頼者の決定（2026-11-18）で、論点ノート（hino-ronten）を、このリポジトリで作り直す。下書き Fable 5.2。

## 0. 目的

このリポジトリは、行政の効率化のためのツールではない。自治体の組織が自律的であること（自分たちで考え、決め、説明できること）を支えるための試みである。

地域の課題は、経歴も得意も違う職員、選挙で選ばれる首長と議員、そして住民の、やりとりの中で解かれていく。そのやりとりの土台として、これまでの経緯（町が何と説明し、議会で何が話され、何が決まり、どこで止まっているか）を、同じ公開資料から、誰もが同じ条件でたどれるようにする。

生成AIには、この経緯の整理を任せる。評価と判断は任せない。

確認するのは、減った時間ではなく、やりとりがどう変わったかである。

## 1. 作る物（変わらない）

滋賀県日野町の計画・予算・議会の公開資料を横断して、論点ごとに「町は何と説明しているか」「議会で何が問われ、どう答えたか」を、原文にたどれる形で出すツール。使うのは、職員、議員、住民と、各自の生成AI。

## 1.1 出口

- 共通の土台：職員・議員・住民が同じ公開資料を、もとの資料までたどれる形で引ける。立場ごとに別の物を作らない。
- 生成AIは準備の下ごしらえ（何が話され、町が何と説明し、どこで議論が止まっているか）。評価と結論は書かず、判断は使う人が行う。
- 道は、MCP（読み取り専用。どの応答にも出典）、画面（事項のページ・年度のページ）、インターネットにつながらない環境でも開ける単一の HTML の3つ。同じ定義から作る。
- 使う場面は、議会対応、予算と決算、計画の策定・見直し・進み具合、事業の運営、引き継ぎ、住民への説明、課をまたぐ連携、政策の検討。最初に通すのは、事項ごとの1枚で「この件の現状と経過、止まっている所」をつかむこと。
- 経緯の整理の中身は、いまの町の説明と値、経過、これまでの議論、止まっている所、言ったこと（予定・試算・目標）と起きたこと（実績）の対。並べるだけで、良し悪しは書かない。
- 確認するのは、やりとりがどう変わったか（経緯を自分でたどれたか。議論が中身から始められたか。過去の議論と止まっている所を踏まえていたか）。使った場面ごとに、起きたことを言葉で記録する。効果を試算で書かない。補助として、前の形との比較と、議会だよりの問と答を参考にした漏れの確認（一致の割合は目標にしない）。
- 使ってもらうときに聞くのは、どの場面のやりとりで、経緯が共有されていないことが妨げになっているか。
- 新しい会議録や資料が入ったら、対応の案がツールで付く所までを作る。
- 項目の表は、担当課が読んで確認できる形にする。
- 考え方のもと：依頼者の note「政策参与のおはなし」その27・その28、「MCPを作って、答弁の下書きを確認してみた」。

## 3. 層（3つ）

1. **もとの資料と ID**：会議録（hino-council-search）、計画と附表（shiga-hino-plans）、町の資料（hino-town-docs）、議員・議案（council-dashboard）。読むだけ。発言・段落・資料・議案の ID と、引用を原文と照合する検査。
2. **定義と決まり**（依頼者が決める。生成AIは案まで）
   - 題材：範囲、資料、議案、選んだ問い
   - 事項：議論の主題だけを事項にする。種類は、課題／取り組み／対象の属性と値。資料と、過程の出来事は、事項にせず、出典と経過として持つ
   - 関係：目的と手段（取り組みが、課題や目的に対処する）、資料が資料のもとになる、出来事が取り組みの根拠になる、取り組みに予算の事業が当たる
   - 項目：何を数えた数値か（基準、単位、いつの数値として数えるか）。資料の間で数値が一致しないときに先に出す資料は、依頼者と担当課が決める
   - 決まり：事項に対応づけるときの決まり（N3 の K1〜K11 がもと）、出すときの規約（もとの資料に無いことを出さない、議員を件数で並べない、未確認の印）
3. **生成**（生成AIが作る）：問いと事項の対応（主題にする／根拠・出典にする）、町の資料から事項ごとに抜いた記載。作り方は、2人が別々に読む → ツールの検査 → 突き合わせ。

出口は §1.1 のとおり。決まりと規約は、使う人の生成AIにも渡せる1つの文書（SKILL.md の形）にする。

## 4. オントロジーとセマンティックの観点

層2（定義と決まり）を、2つの観点で分けて持つ。

### 4.1 セマンティック：項目（何を数えた数値か）

同じ名前の数字でも、資料・時点・基準で値が違う。何を数えた数値かの定義と、時点ごとの数値を、2つの表に分けて持つ（2026-11-19 の依頼者の決定。表の形は SCHEMA.md §6）。下の表は、項目と数値で持つものの例。

| 持つもの | 例（幼保の待機児童） | 例（予算） |
| --- | --- | --- |
| 基準（何を数えた数か） | 国基準の待機児童数／潜在的待機児童数／不承諾を通知した児童数 | 当初予算／補正後の予算／決算 |
| 資料（どこに書いてあるか） | 再編整備計画 21ページ、会議録の答弁 | 附表、補正予算の概要、決算の資料 |
| 時点・対象の年度 | 令和6年4月1日現在 | 対象の年度（議案から決める）と、議決の日 |
| 単位 | 人 | 千円 |
| 値の性質 | 実績（4月1日現在の数） | 見込み（予算）／実績（決算）。計画の指標は、目標と実績 |

決まり：
- 値は資料の原文から引く。生成AIに計算や集計をさせない。
- 基準の違う数を、同じ数として並べない。並べるときは基準の名前を付ける。
- 対象の年度（何年度の予算・決算か）と、出来事の日（いつ議決・答弁したか）を分けて持つ。
- 値の性質（目標・予定・試算・見込み・実績、推計か実測か）を持つ。性質の違う値を、同じ数として並べない。予定・試算・目標と実績は、対にして並べる。
- 資料に書かれていない数値を、推定で埋めない。数値が無い場合は、状態（欄が空、数値を示さない説明がある、調べた範囲に見つからない）を書き、「無い」とだけ書かない（SCHEMA.md §6.3）。
- 資料の間で数値が一致しないときは、両方を持つ。どちらかを消さない。

### 4.2 オントロジー：何があり、どうつながるか

**物の種類**

| 種類 | 何か | 例 | 役割 |
| --- | --- | --- | --- |
| 課題 | 町が解くべきとしている問題 | 保育士の人材不足、園舎の耐用年数の超過 | 事項（議論の主題） |
| 取り組み | 施策・事業・方針 | 幼児教育保育施設の再編整備、民間事業者による小規模保育施設の整備 | 事項（議論の主題） |
| 対象の属性と値 | 取り組みや施設の、数・時期・場所・費用 | 待機児童数、新こども園の用地・面積・定員・整備費用と財源・開園時期 | 事項（議論の主題）。値は 4.1 の項目による |
| 資料と、資料の中の場所 | 計画、提言、基本構想、その章や見出し | 懇話会の提言、再編整備計画（案）、想定3 | 出典。事項にしない |
| 過程の出来事 | 会議、調査、意見の聴取、議決 | 先進地の現地調査、ワークショップ、パブリックコメント、議決 | 経過。事項にしない |
| 施設・地区・組織 | 物と場所と主体 | 鎌掛分園、必佐地区、子ども支援課 | 見方（絞り込みの軸） |
| 問い・質疑・報告 | 議会の記録の単位 | 一般質問の1問、議案質疑、委員長の報告 | 対応を付ける相手 |

**物どうしの関係**

| 関係 | 例 |
| --- | --- |
| 目的と手段（取り組みが、課題や目的に対処する） | 適正な集団規模の確保 ← 幼保連携型認定こども園の新設 |
| 資料が、事項について記す | 再編整備計画 21ページ → 待機児童数 |
| 資料が、資料のもとになる | 提言 → 計画（案） → 計画 → 基本構想 |
| 出来事が、取り組み・資料の根拠になる | 千代地区の視察 → 小規模保育の進め方 |
| 取り組みに、予算の事業が当たる | 新こども園の整備 → 実施計画 e008、附表の事業 |
| 事項が、分類の体系の要素に入る | 待機児童数 → 計画の「現状と課題」 |
| 資料の数字が、別の資料から引かれている（確認してから足す） | 計画の値 → もとの調査 |
| 質問の題が、分類の体系の要素に入る | 一般質問の題 → 総合計画の分野（①子ども・子育てなど）。2026-11-28 の依頼者の決定。事項ではなく、一般質問の台帳の題を、分野に結び付ける（SCHEMA.md 7.11） |

**問いと、物との関係（3つに分ける）**

| 関係 | 意味 | 持ち方 |
| --- | --- | --- |
| 主題にする | その事項について、中身や結果・評価・理由や根拠・踏まえた対応を、問うているか答えている | 問いと事項の対応として持つ。事項のページに出す |
| 根拠・出典にする | 別の主題を論じるために、資料や出来事を引いている | 問いと資料・出来事の関係として持つ。資料のページ、経過から出す |
| 言及する | 経過や前置きで名前を挙げただけ | 持たない。語で会議録を探すツールで届く |

**規約（出すときに守ること）**：もとの資料に無いことを出さない。引用と値は原文と照合する。未確認の対応には印を付ける。議員を件数で並べたり比較したりしない。

### 4.3 持ち方

- 種類と関係は、表（TSV）で持つ。OWL や RDF では書かない。読むだけのツールで、エージェントが業務を実行するための権限や行動の規約は要らないため。
- 定義の整合はツールで検査する（事項の種類、関係の両端、値の基準・資料・時点、対応の事項と範囲）。定義と決まりは1か所にだけ書き、MCP の説明・画面の文言・作業者への指示に書き写さない。
- 語は、分類の上下は SKOS、資料の派生は PROV、議会の発言の構造は Akoma Ntoso を参考にする。丸ごとは取り入れない。
- 種類・関係・定義を足すときは、進め方の決まり2（足す前に比較する）に従う。上の表は出発点の案で、幼保で通して、使わなかった種類と関係は外す。

## 5. 進め方の決まり（3つ）

1. 人が決めるのは定義と決まりまで。1件ずつは生成AIが付け、未確認の印で出す。
2. 足す前に、足した形と足さない形を同じ問いで比較し、差を数で示す。差が出ないものは足さない。
3. 題材1つを通すたびに、使う人に見せる。

守ることは前と同じ：捏造しない、入力は読むだけ、全文を複製しない、議員を序列化しない、ライセンスの区分。

## 7. 工程（幼保で通す）

| 段階 | 行うこと | 依頼者が決めること | できた、と言える条件 |
| --- | --- | --- | --- |
| R0 | この方針と保存先（hino-context）を決め、手順書と、ID ・照合のツールを移す | 方針、保存先 | 手順書が2ページ程度で書けている。移したツールの検査が通る |
| R1 | いまある物（確定済みの対応、町の資料の記載、比較で作ったツール）で、事項の1枚の見本を2〜3事項ぶん作り、使う人に使ってもらう。どの場面のやりとりで、経緯が共有されていないことが妨げになっているかを聞く | 見本に使う事項、見せる相手と場 | 場面ごとに、起きたことと、足りなかった点の記録がある |
| R2 | R1 で足りないと分かった所から、幼保の事項を主題（課題・取り組み・属性と値）に整理し、数字の定義と関係を足す | 事項の一覧（1回）、数字の定義 | 主題に絞った場合の2人の一致を、N3 の結果から数え直してある |
| R3 | 選んだ問い全部に、生成AIの2回の読み取りで対応を付ける。新しい会議録に対応の案が付くツールにする | 分かれ方から見つかった決まりの不備 | 2人の一致の割合と、分かれた組の一覧が出ている。議会だよりとの比較で、漏れの候補が出ている |
| R4 | MCP・画面・単一の HTML を定義から作り、同じ問いで A・B・C と比較し、もう一度使ってもらう | 画面の見本 | 補助の比較で、必須の語が A の20以上、確認項目が B・C の10〜11以上（届かなければ理由を数で示して止まる）。使った場面ごとに、やりとりがどう変わったかの記録がある |

そのあと、介護、公共施設、地域のあり方の順に、R1〜R4 を繰り返す。

### 7.1 工程の修正（2026-11-27）

依頼者が了承した MCP の試作の文案（Project の `claude/hino-context-R2/mcp-an-2026-11-27.md` 8節）により、上の表を次のように修正する。表そのものは、決めた時の形のまま残す。

| 点 | 修正前 | 修正後 |
| --- | --- | --- |
| R4（MCP・画面・単一の HTML を作る段階）の MCP | R2（資料の整理）と R3（議会の問いとの関係）を済ませてから作る | R2 の途中で、MCP の試作を先に作って使う（R4 の一部を前に出す）。形は docs/mcp.md |
