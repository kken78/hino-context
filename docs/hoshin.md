# hino-context の方針（2026-11-18）

依頼者の決定（2026-11-18）で、論点ノート（hino-ronten）を、このリポジトリで作り直す。下書き Fable 5.2。

## 0. 目的

このリポジトリは、行政の効率化のための道具ではない。自治体の組織が自律的であること（自分たちで考え、決め、説明できること）を支えるための試みである。

地域の課題は、経歴も得意も違う職員、選挙で選ばれる首長と議員、そして住民の、やりとりの中で解かれていく。そのやりとりの土台として、これまでの経緯（町が何と説明し、議会で何が話され、何が決まり、どこで止まっているか）を、同じ公開資料から、誰もが同じ条件でたどれるようにする。

生成AIには、この経緯の整理を任せる。評価と判断は任せない。

確かめるのは、減った時間ではなく、やりとりがどう変わったかである。

## 1. 作る物（変わらない）

滋賀県日野町の計画・予算・議会の公開資料を横断して、論点ごとに「町は何と説明しているか」「議会で何が問われ、どう答えたか」を、原文にたどれる形で出す道具。使うのは、職員、議員、住民と、各自の生成AI。

## 1.1 出口

- 共通の土台：職員・議員・住民が同じ公開資料を、原典までたどれる形で引ける。立場ごとに別の物を作らない。
- 生成AIは準備の下ごしらえ（何が話され、町が何と説明し、どこで議論が止まっているか）。評価と結論は書かず、判断は使う人が行う。
- 道は、MCP（読み取り専用。どの応答にも出典）、画面（事項のページ・年度のページ）、閉域でも開ける単一の HTML の3つ。同じ定義から作る。
- 使う場面は、議会対応、予算と決算、計画の策定・見直し・進み具合、事業の運営、引き継ぎ、住民への説明、課をまたぐ連携、政策の検討。最初に通すのは、事項ごとの1枚で「この件の現状と経過、止まっている所」をつかむこと。
- 経緯の整理の中身は、いまの町の説明と値、経過、これまでの議論、止まっている所、言ったこと（予定・試算・目標）と起きたこと（実績）の対。並べるだけで、良し悪しは書かない。
- 確かめるのは、やりとりがどう変わったか（経緯を自分でたどれたか。議論が中身から始められたか。過去の議論と止まっている所を踏まえていたか）。使った場面ごとに、起きたことを言葉で記録する。効果を試算で書かない。補助として、前の形との比べと、議会だよりの問と答を参考にした落ちの探し（一致の割合は目標にしない）。
- 使ってもらうときに聞くのは、どの場面のやりとりで、経緯が共有されていないことが妨げになっているか。
- 新しい会議録や資料が入ったら、対応の案が道具で付く所までを作る。
- 定義の表は、担当課が読んで確かめられる形にする。
- 考え方のもと：依頼者の note「政策参与のおはなし」その27・その28、「MCPを作って、答弁の下書きを確かめてみた」。

## 3. 層（3つ）

1. **原典と鍵**：会議録（hino-council-search）、計画と附表（shiga-hino-plans）、町の資料（hino-town-docs）、議員・議案（council-dashboard）。読むだけ。発言・段落・資料・議案の鍵と、引用を原文と照らす検査。
2. **定義と決まり**（依頼者が決める。生成AIは案まで）
   - 題材：範囲、資料、議案、選んだ問い
   - 事項：議論の主題だけを事項にする。種類は、課題／取り組み／対象の属性と値。文書と、過程の出来事は、事項にせず、出典と経過として持つ
   - 関係：取り組みが課題に対処する、文書が文書のもとになる、出来事が取り組みの根拠になる、取り組みに予算の事業が当たる
   - 数字の定義：どの資料の、どの時点の、どの基準の値を正とするか
   - 決まり：事項に当てるときの決まり（N3 の K1〜K11 がもと）、出すときの規約（原典に無いことを出さない、議員を件数で並べない、未確認の印）
3. **生成**（生成AIが作る）：問いと事項の対応（主題にする／根拠・出典にする）、町の資料から事項ごとに抜いた記載。作り方は、2人が別々に読む → 道具の検査 → 突き合わせ。

出口は §1.1 のとおり。決まりと規約は、使う人の生成AIにも渡せる1つの文書（SKILL.md の形）にする。

## 4. オントロジーとセマンティックの観点

層2（定義と決まり）を、2つの観点で分けて持つ。

### 4.1 セマンティック：数字の定義（どの値を正とするか）

同じ名前の数字でも、資料・時点・基準で値が違う。値ごとに、次を定義として持つ。

| 持つもの | 例（幼保の待機児童） | 例（予算） |
| --- | --- | --- |
| 基準（何を数えた数か） | 国基準の待機児童数／潜在的待機児童数／不承諾を通知した児童数 | 当初予算／補正後の予算／決算 |
| 資料（どこに書いてあるか） | 再編整備計画 21ページ、会議録の答弁 | 附表、補正予算の概要、決算の資料 |
| 時点・対象の年度 | 令和6年4月1日現在 | 対象の年度（議案から決める）と、議決の日 |
| 単位 | 人 | 千円 |
| 値の性質 | 実績（4月1日現在の数） | 見込み（予算）／実績（決算）。計画の指標は、目標と実績 |

決まり：
- 値は資料の原文から引く。生成AIに計算や集計をさせない。
- 基準の違う数を、同じ数として並べない。並べるときは基準の名前を付ける。
- 対象の年度（何年度の予算・決算か）と、出来事の日（いつ議決・答弁したか）を分けて持つ。
- 値の性質（目標・予定・試算・見込み・実績、推計か実測か）を持つ。性質の違う値を、同じ数として並べない。予定・試算・目標と実績は、対にして並べる。
- 正とする資料が無い値は、無いと出す。推定で埋めない。

### 4.2 オントロジー：何があり、どうつながるか

**物の種類**

| 種類 | 何か | 例 | 役割 |
| --- | --- | --- | --- |
| 課題 | 町が解くべきとしている問題 | 保育士の人材不足、園舎の耐用年数の超過 | 事項（議論の主題） |
| 取り組み | 施策・事業・方針 | 幼児教育保育施設の再編整備、民間事業者による小規模保育施設の整備 | 事項（議論の主題） |
| 対象の属性と値 | 取り組みや施設の、数・時期・場所・費用 | 待機児童数、新こども園の用地・面積・定員・整備費用と財源・開園時期 | 事項（議論の主題）。値は 4.1 の定義による |
| 文書と、文書の部分 | 計画、提言、基本構想、その章や見出し | 懇話会の提言、再編整備計画（案）、想定3 | 出典。事項にしない |
| 過程の出来事 | 会議、調査、意見の聴取、議決 | 先進地の現地調査、ワークショップ、パブリックコメント、議決 | 経過。事項にしない |
| 施設・地区・組織 | 物と場所と主体 | 鎌掛分園、必佐地区、子ども支援課 | 見方（絞り込みの軸） |
| 問い・質疑・報告 | 議会の記録の単位 | 一般質問の1問、議案質疑、委員長の報告 | 対応を付ける相手 |

**物どうしの関係**

| 関係 | 例 |
| --- | --- |
| 取り組みが、課題に対処する | 再編整備 → 園舎の耐用年数の超過 |
| 文書が、事項について記す | 再編整備計画 21ページ → 待機児童数 |
| 文書が、文書のもとになる | 提言 → 計画（案） → 計画 → 基本構想 |
| 出来事が、取り組み・文書の根拠になる | 千代地区の視察 → 小規模保育の進め方 |
| 取り組みに、予算の事業が当たる | 新こども園の整備 → 実施計画 e008、附表の事業 |
| 事項が、分類の体系の要素に入る | 待機児童数 → 計画の「現状と課題」 |
| 資料の数字が、別の資料から引かれている（確かめてから足す） | 計画の値 → もとの調査 |

**問いと、物との関係（3つに分ける）**

| 関係 | 意味 | 持ち方 |
| --- | --- | --- |
| 主題にする | その事項について、中身や結果・評価・理由や根拠・踏まえた対応を、問うているか答えている | 問いと事項の対応として持つ。事項のページに出す |
| 根拠・出典にする | 別の主題を論じるために、文書や出来事を引いている | 問いと文書・出来事の関係として持つ。文書のページ、経過から出す |
| 言及する | 経過や前置きで名前を挙げただけ | 持たない。語で会議録を探す道具で届く |

**規約（出すときに守ること）**：原典に無いことを出さない。引用と値は原文と照らす。未確認の対応には印を付ける。議員を件数で並べたり比べたりしない。

### 4.3 持ち方

- 種類と関係は、表（TSV）で持つ。OWL や RDF では書かない。読むだけの道具で、エージェントが業務を実行するための権限や行動の規約は要らないため。
- 定義の整合は道具で検査する（事項の種類、関係の両端、値の基準・資料・時点、対応の事項と範囲）。定義と決まりは1か所にだけ書き、MCP の説明・画面の文言・作業者への指示に書き写さない。
- 語は、分類の上下は SKOS、文書の派生は PROV、議会の発言の構造は Akoma Ntoso を参考にする。丸ごとは取り入れない。
- 種類・関係・定義を足すときは、進め方の決まり2（足す前に比べる）に従う。上の表は出発点の案で、幼保で通して、使わなかった種類と関係は外す。

## 5. 進め方の決まり（3つ）

1. 人が決めるのは定義と決まりまで。1件ずつは生成AIが付け、未確認の印で出す。
2. 足す前に、足した形と足さない形を同じ問いで比べ、差を数で示す。差が出ないものは足さない。
3. 題材1つを通すたびに、使う人に見せる。

守ることは前と同じ：捏造しない、入力は読むだけ、全文を複製しない、議員を序列化しない、ライセンスの区分。

## 7. 工程（幼保で通す）

| 段 | 行うこと | 依頼者が決めること | できた、と言える条件 |
| --- | --- | --- | --- |
| R0 | この方針と置き場所（hino-context）を決め、手順書と、鍵・照合の道具を移す | 方針、置き場所 | 手順書が2ページ程度で書けている。移した道具の検査が通る |
| R1 | いまある物（確定済みの対応、町の資料の記載、比べで作った道具）で、事項の1枚の見本を2〜3事項ぶん作り、使う人に使ってもらう。どの場面のやりとりで、経緯が共有されていないことが妨げになっているかを聞く | 見本に使う事項、見せる相手と場 | 場面ごとに、起きたことと、足りなかった点の記録がある |
| R2 | R1 で足りないと分かった所から、幼保の事項を主題（課題・取り組み・属性と値）に整理し、数字の定義と関係を足す | 事項の一覧（1回）、数字の定義 | 主題に絞った場合の2人の一致を、N3 の結果から数え直してある |
| R3 | 選んだ問い全部に、2人読みで対応を付ける。新しい会議録に対応の案が付く道具にする | 分かれ方から見つかった決まりの穴 | 2人の一致の割合と、分かれた組の一覧が出ている。議会だよりとの見比べで、落ちの候補が出ている |
| R4 | MCP・画面・単一の HTML を定義から作り、同じ問いで A・B・C と比べ、もう一度使ってもらう | 画面の見本 | 補助の比べで、外せない語が A の20以上、鍵になる材料が B・C の10〜11以上（届かなければ理由を数で示して止まる）。使った場面ごとに、やりとりがどう変わったかの記録がある |

そのあと、介護、公共施設、地域のあり方の順に、R1〜R4 を繰り返す。
